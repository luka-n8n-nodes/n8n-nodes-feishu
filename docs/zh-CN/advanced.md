## 事件接入：长连接还是 Webhook

“事件”是飞书发生某件事后的通知，例如用户发来消息。“触发器”接收通知并启动工作流。

| 对比项 | 飞书 Trigger | 飞书 Webhook Trigger |
| --- | --- | --- |
| 接入方式 | n8n 主动建立 WebSocket 长连接 | 飞书向 n8n 的回调地址发送 HTTP 请求 |
| 网络条件 | n8n 能访问飞书服务，无需公网回调地址 | 回调地址必须可被飞书访问 |
| 飞书后台选择 | 使用长连接接收事件 | 将事件/回调发送至开发者服务器 |
| 凭证 | 应用级别凭证 | 应用级别凭证 |
| 适合的情况 | 使用企业自建应用，希望省去回调地址配置 | 已有可访问的回调服务，或需要服务器回调接入 |

飞书长连接模式支持企业自建应用。平台允许同一应用建立多个连接，但同一事件只会推送给其中一个客户端，**不会广播给所有客户端**。因此建议一个应用使用一个接收入口，再按事件类型分流到后续处理；多个独立触发器即使筛选不同事件，也不能保证各自收到预期事件。测试连接和生产连接也可能分流事件。[飞书长连接说明](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)

当前节点界面仍可能显示“每个应用只能运行一个 Trigger”的提示，应理解上述分发行为及单入口建议，不应将提示当作飞书只允许一个连接的硬性限制。

### 后台订阅与节点筛选是两步

1. 在飞书开发者后台，为应用添加需要的事件或回调，开通对应权限，并按要求发布生效。
2. 在 n8n 触发器中选择要接收的事件类型。默认选择所有事件，含义是“不按类型过滤已收到的事件”；它不会替你修改飞书后台的订阅列表。

先检查后台有没有推送，再检查节点是否过滤。选择“所有事件”不会扩大应用权限，也不会让未订阅的事件自动出现。

### 配置长连接

1. 在 n8n 添加「飞书 Trigger」，选择应用凭证与所需事件类型。普通通知先使用 `Immediately` 响应模式。
2. 开始测试监听，使连接在线；在飞书后台选择长连接订阅方式并保存配置，添加所需事件及权限。
3. 在飞书中触发目标事件，检查 n8n 输出。测试完成后停止测试监听，将工作流激活或发布为生产运行状态（名称随 n8n 版本而异）。

如果同一应用已有生产连接，测试时要考虑上述分流行为；可用独立测试应用验证流程。

### 配置 Webhook

1. 添加「飞书 Webhook Trigger」，选择应用凭证。测试时先开启监听，再复制节点生成的 Test URL；生产使用 Production URL，并让工作流处于生产运行状态。
2. 将对应 URL 配置到飞书后台的服务器回调订阅方式中。测试 URL 仅在测试监听期间可用，不能长期代替生产 URL。
3. 若飞书开启加密推送，在节点填写同一个 `Encrypt Key`；收到加密请求却未填写时，节点无法解密。
4. 如需校验 Verification Token，开启界面中的「验证应用标识」并填写 `Verification Token`。这个开关实际控制 Token 校验，默认关闭；普通事件的 `app_id` 与凭证应用匹配检查另行执行。
5. 保存回调配置时，节点会处理 `url_verification` 地址验证，返回 `challenge`，不会为这次验证启动业务工作流。随后添加所需事件/回调与权限，并测试实际业务事件。

普通事件的应用 ID 不匹配或事件类型被过滤时，节点会确认收到但不启动工作流。不要仅凭 HTTP 200 判断工作流已执行。部署代理及地址配置应遵循你的 n8n 部署要求。[飞书服务器回调说明](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/step-1-choose-a-subscription-mode/send-callbacks-to-developers-server)

## 同步响应与发送消息

- **发送消息**：在「飞书」节点选择 `消息 → 发送消息`，向指定人或群发送聊天内容。
- **同步响应**：用「飞书响应」节点，向本次飞书事件或回调返回处理结果，例如卡片交互的提示。它不是聊天消息发送器。

| 触发器的响应模式 | 行为 |
| --- | --- |
| Immediately | 收到事件后尽快确认，不等待工作流处理完成，适合普通通知处理 |
| Using '飞书响应' Node | 需要自定义同步结果时使用，并在流程中接入「飞书响应」节点 |

「飞书响应」中的 `同步响应模式` 必须与触发器对应：长连接选界面原名「长链接同步响应」，Webhook 选「Webhook 同步响应」。本包的 Webhook 触发器应配合本包的响应节点。

`响应内容` 支持 `No Data` 和 `JSON`。当前实现的 `No Data` 返回空对象 `{}`；`JSON` 返回你填写的对象，其结构必须符合对应飞书回调的要求。输入多个数据项时，**只把第一项的响应发回飞书**。默认节点输出是响应内容；开启「启用响应输出分支」后，分别输出原始输入和响应内容。

长连接中，`card.action.trigger`、`url.preview.get`、`profile.view.get` 才进入等待自定义响应的路径，固定等待上限为 **3 秒**；超时或出错会记录警告并返回空对象。普通事件不会等待后续响应节点。Webhook 应遵守对应飞书回调的时限，不能套用一个“可无限等待”的假设。将同步结果放在能迅速完成的路径上，耗时处理安排在响应之后或独立流程中。

<a id="data"></a>

## 输入输出：从执行数据连接下一步

n8n 用数据项（item）在节点间传递数据，通常包括 `json`，文件还可能包含 `binary`。参数可以填写固定值，也可通过 n8n 表达式引用上游数据。

| 情况 | 当前输出行为 |
| --- | --- |
| 普通 API 操作 | 通常输出接口 `data` 中的数据，而非完整 `code / msg / data` 外壳；具体操作可能进一步拆分列表或转换格式 |
| 长连接触发器 | 事件内容被展开到顶层，事件类型可通过 `{{$json.event_type}}` 读取 |
| Webhook 触发器 | 输出解密后的原始事件结构；2.0 事件类型在 `{{$json.header.event_type}}`，1.0 在 `{{$json.event.type}}` |
| 多维表格 Get row(s) | 默认返回记录；开启「转换数据」会改变字段值的表示方式，需重新检查下游映射 |
| 上传 / 下载 | 按操作要求读取或生成 Binary 数据，字段名以该操作配置和实际输出为准 |

切换触发器类型时，不要直接沿用原表达式路径。先执行一次查看 Output，再从真实数据中拖拽字段或创建表达式。多数操作按输入项执行；列表查询可能输出多项，后续发送消息节点也可能因此执行多次。Insert row / Update row(s) 会聚合输入做批量写入，不能据输入项数量直接推断 API 请求数。

<a id="bitable"></a>

## 多维表格：字段映射与增强操作

“记录”对应表格中的一行，“字段”对应一列。可先用 `解析多维表格地址` 提取 `app_token` 与 `table_id`，再分别填写「多维表格 App 的唯一标识」与「多维表格数据表的唯一标识」。若链接没有数据表 ID，需选择具体数据表后取其链接或通过「列出数据表」获取。

### 如何选择操作

| 目标 | 选择的操作 | 要点 |
| --- | --- | --- |
| 按条件读取记录 | 多维表格 - Get row(s) | 可配置 Match、排序、字段筛选、Return All 和转换数据 |
| 新增记录 | 多维表格 - Insert row | 用字段映射填写 Values to Insert；支持跨输入项批量写入 |
| 更新已知记录 | 多维表格 - Update row(s) | 必须提供 Record ID，用 Values to Update 映射字段；按条件更新时先查询得到记录 ID |
| 匹配则更新，没有则新增 | 多维表格 - Upsert row(s) | 用 Match 配置匹配条件，用 Values to Upsert 设置写入字段 |
| 删除匹配记录 | 多维表格 - Delete row(s) | 按条件查找并删除匹配记录；先用查询确认条件覆盖范围 |
| 满足存在 / 不存在条件才继续 | 多维表格 - If row exists / If row does not exist | 满足条件时透传原始输入，否则不输出；不是带 true / false 两个出口的 IF 节点 |
| 可视化创建数据表 | 多维表格 - Create a Data Table | 配置初始字段类型与属性 |

如果已有符合飞书接口要求的参数或 JSON，可以使用「新增记录」「更新记录」「批量新增记录」等基础操作；需要在界面映射列和值时，优先查看上表的增强操作。

### 字段与条件怎么填

- **字段映射（Resource Mapper）**：在 Values to Insert / Update / Upsert 中，将目标字段对应到固定值或上游数据。字段列表由当前表的元数据加载。
- **自动映射（Auto Map）**：适用于上游字段名与表格字段名一致的数据；仍要检查字段类型。附件字段使用上游 Binary 字段名，如 `data`，不是本地文件路径；多个 Binary 名称用英文逗号分隔。
- **匹配条件（Match / Must Match）**：选择 Column Name or ID、Condition、Value。运算符按字段类型加载；Combine Conditions 的 Any Condition 表示任一条件满足，All Conditions 表示全部满足。按多个字段联合定位记录时，要明确选择 All Conditions。

### Upsert 的具体边界

假设用订单号 `A-001` 匹配，将订单状态写为“已发货”：找到记录则更新，没有记录则新建。需要同时配置匹配条件和至少一个有效写入字段；**匹配条件不会自动成为新记录的字段值**，新建时也需要订单号，就将其放入 Values to Upsert。

若匹配多条记录，当前实现只更新接口返回的第一条。建议使用业务唯一字段，并先清理重复记录。它是“先查询、再更新或创建”的组合操作，不提供数据库唯一约束；并发处理相同业务键仍可能产生重复数据。

输出会增加 `_upsert_action`（`update` 或 `insert`）和 `_upsert_matched_count`（匹配数量；无匹配时为 `0`）。默认批次行为见下文，不能理解为固定每秒 10 次 API 请求。

<a id="pagination"></a>

## 自动分页（Return All）与递归

支持 Return All 的 26 项操作已在[操作参考](./operations.md)标记，包括「获取文件访问记录」「搜索云文档」。

- 默认关闭：根据操作的 Limit 获取限定数量的结果。
- 开启后：自动翻页获取当前身份有权限访问、且满足筛选条件的全部结果。大量数据可能带来更多请求和更长执行时间。
- **递归**：进入子部门、子文件夹或知识库子节点继续查询。这与同一层结果的分页不同，需要在支持递归的操作中另行配置；打开 Return All 本身不等于递归遍历。

<a id="batching"></a>

## 批次（Batching）与超时（Timeout）

仅在提供这些选项的操作中配置，通常位于 `Options`。

| 选项 | 实际含义 |
| --- | --- |
| Items per Batch | 每批启动的输入项处理数量，不是每批 HTTP 请求的精确数量 |
| Batch Interval (Ms) | 启动下一批前的等待间隔（毫秒）；不会等待上一批全部完成，批次可能重叠 |
| Timeout | 请求超时配置（毫秒），不是整个工作流的执行时限；`0` 表示不在此选项设置超时限制，实际仍受运行环境影响 |

普通逐项操作未配置 Batching 时通常串行处理；添加 Batching 才启用并发。Insert row / Update row(s) 等具有独立的批量实现，不应套用逐项执行模型。

**Upsert 例外：默认启用并发，每批 10 个输入项，批次启动间隔 1000 毫秒。** 一个输入项还可能执行字段查询、记录查询、附件上传及写入，因此这不是“10 次 API 请求/秒”，也不是总并发数的硬上限。发生限流时，减少批次大小、增加间隔，并按实际接口的限流规则调整。

<a id="troubleshooting"></a>

## 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 凭证有效，但读写文档或表格失败 | 分别核对接口权限、发布审批、资源协作者角色；不要只检查 App ID 和 App Secret |
| 搜索用户或搜索云文档失败 | 两项操作仅支持用户凭证；确认用户已授权业务权限且能访问目标数据 |
| 触发器没有收到事件 | 检查后台订阅及权限、工作流监听/生产状态、节点筛选、网络，以及其他长连接是否分流事件 |
| Webhook 验证或解密失败 | 测试地址是否正在监听，生产地址是否启用；Encrypt Key 与可选的 Verification Token 是否匹配 |
| Webhook 返回成功却没执行 | 地址验证不启动工作流；检查 app_id 是否匹配、事件是否被过滤 |
| 卡片交互无响应或长连接响应超时 | 核对触发器和响应节点模式，在 3 秒内到达长连接响应节点；移开耗时请求 |
| 多维表格字段列表为空 | 检查凭证、资源权限、app_token 和 table_id；更新表结构后重新加载字段 |
| If row exists 后流程没有继续 | 未满足条件时不输出数据，这是该操作的预期行为 |
| Upsert 只修改了一条重复记录 | 当前只更新首条匹配；检查匹配条件与业务键唯一性 |
| 收到多条重复通知 | 查看上游输出了多少 item、工作流是否重复执行，以及事件是否重推；按业务需要设计去重 |
| 大量请求触发限流 | 降低批次大小并增加间隔；Return All、附件和封装操作都可能增加请求数 |

保留原始错误码、操作名称、包版本与 n8n 版本，再到[飞书文档搜索](https://open.feishu.cn/search)查询，或提交[已脱敏的问题反馈](https://github.com/luka-n8n-nodes/n8n-nodes-feishu/issues)。
